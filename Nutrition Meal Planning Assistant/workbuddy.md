## Day 1 · 2026-10-15

### 1.1 用户定义「麦当劳全能智能点餐 Skill」角色（参赛用）

**用户诉求**：定义一个点餐 Skill，具备 5 大能力、3 套 SOP，并附加强制约束——所有餐品、价格、营养、门店、优惠**必须来自官方 MCP**，禁止编造；输出用 Markdown 表格 + 标题式开头；401 / 429 使用固定话术；营养信息仅作饮食参考、不做医疗诊断。

**处理**：
- 落为用户级 Skill：`~/.workbuddy/skills/mcdonald-order/SKILL.md`。
- **当时 MCP 尚未连接**（`~/.workbuddy/mcp.json` 不存在，可用工具里没有 `query-meals` 等），已如实告知用户，**未编造任何餐品或价格数据**。

### 1.2 抓取官方文档并按文档重写 Skill

**用户诉求**：按 open.mcd.cn 的官方文档开发，不要凭社区二手资料。

**难点**：`open.mcd.cn/mcp/doc` 是 React SPA，直接抓取是空壳。

**解法**：下载前端 chunk `/static/js/index.<hash>.chunk.js`，把里面的 `\uXXXX` 反转义还原（emoji 代理对需 `encode('utf-16','surrogatepass').decode('utf-16')`），从 `# 1. 申请 MCP Token` 起截取即为 Markdown 全文。

**产出**：`SKILL.md` + `references/mcp-tools.md`（33 工具速查 + 枚举字典 + 错误码）+ `references/ordering-pipeline.md` + `references/official-doc.md` + `scripts/probe.py`。

**关键结论**：
- 官方文档为 **33 个工具**（社区流传的 35 个中，`query-promotions` / `query-survey-coupon` 未文档化）。
- 官方工具名写作 `query-party-store-date`，文档此处为笔误，实际以 `tools/list` 返回为准。

### 1.3 MCP 接通

用户提供 Token（**本记录不保存 Token 值**），写入 `~/.workbuddy/mcp.json`：端点 `https://mcp.mcd.cn`（根路径）、`streamablehttp`、Header Bearer 鉴权。实测 `tools/list` 返回 **35 个工具**，`now-time-info` 调用成功返回真实服务器时间。

新增 `scripts/call.py`：连接器未启用时的直连兜底通道，并把 `create-order` 等 7 个工具列为 WRITE_TOOLS 提示副作用。

### 1.4 站点初版交付（6 页）

**产出目录**：`nutrition-assistant/`，6 个页面 + 深色全息设计系统，公共库 `core.js` 导出 `window.MCD`。

**数据快照**（全部来自官方 MCP）：营养 160 条、门店 5 家（南京新街口）、菜单 116 款 / 15 分类、套餐详情 33 款。数据内联为 `data-embed.js`，**不走 fetch**，`file://` 直开也能跑。

### ⚠️ 本日最重要的一个 bug：套餐被近似匹配成单品

**现象**：若用「长度差 ≤ 3 的包含匹配」把菜单项对到营养表，会出现「麦辣鸡腿汉堡**三件套** → 麦辣鸡腿汉堡」的错配，**套餐热量被严重低估**。

**根因**：官方营养表只收录**单品**，而菜单里大量是**套餐**（三件套 / 四件套 / 随心配 / 分享餐…）。

**最终规则**：
1. 含组合词（套餐 / 三件套 / 四件套 / 随心配 / 分享餐 / 任选 / 双人 / 多人…）**一律不做近似匹配**；
2. 仅允许「完全同名」+「仅规格前后缀差异（中杯 / 大杯 / 冰 / 热 / 盒装）」+ 3 条明确别名（薯条→中薯条、麦乐鸡→麦乐鸡5块、麦辣鸡翅→麦辣鸡翅-2块）；
3. 近似匹配必须在 UI 标注实际「营养来源」。

**结果**：116 款菜单中 **33 款**可参与配餐（19 精确 + 14 规格差异），套餐类不参与热量计算。

## Day 2 · 2026-10-16

### 2.1 用户反馈：仪表盘 X 轴文字压成一团

**根因**：`lineSVG()` 用「点数 > 8 时 `i % 2` 抽稀」的固定规则，33 点 → 17 个标签，相邻间距 36px，而中文标签实宽 60~66px，必然重叠。

**解法**：新增 `textWidth(s, fs)`（全角 1em、其余 0.56em）估算 SVG 文本宽度 → `pitch = 最宽标签 + 12` → `stride = ceil(pitch / step)` 打标签；首尾点保证有标签；边缘用 `text-anchor` 防越界；每个数据点加刻度线 + `<title>`，未标注名称的点信息不丢。

**验证**：33 款真实数据 → 6 个标签、重叠 0、最窄间隙 40.5px；另测单点 / 两点 / 超长名 / 120 英文 / 空数据六组边界均通过。

### 2.2 用户反馈：雷达图数值压住轴名

**根因**：轴名在 `1.3R`、数值在 `1.16R`，沿同一条半径排列。正上方轴看着没事，斜向轴（蛋白 / 碳水 / 钠）两点横向只差约 14px，必然相交。

**解法**：轴名固定 `1.26R`，数值放在轴名**正下方 13px**（垂直堆叠，不再沿半径排），并做左右夹取与底部上移保护。

### 2.3 用户要求：详情页「套餐组成」移到剖面拆解视图下方

只对 DOM 顺序做调整（给左栏加一层容器，与右栏对称），JS 与 id 不变。窄屏阅读顺序变为：剖面拆解 → 套餐组成 → 官方营养数据 → 相对参考值占比。

### 2.4 用户要求：雷达图改为「占每日推荐摄入量 %」归一化

**原因**：各指标单位不同，用原始数值画顶点没有可比性。

**实现**：新增 `DAILY = { energyKcal: 2000, protein: 60, fat: 60, carbohydrate: 250, sodium: 2000 }`；`pct = value / cap * 100`；同心刻度环 0 / 25 / 50 / 75 / 100%；超标维度顶点与相邻边标红 `#ff5a5f`；顶点组 `class="rvert over"`；悬浮 tooltip 四要素（名称 / 当前值 / 每日推荐 / 占比）。

> 注：`REF`（单人单餐参考值 840 / 22 / 25 / 120 / 800）保留给环形图与占比条，**两者不混用**。

### 2.5 重做门店定位与选择器

**调查发现（重要）**：接口快照 5 家门店的 `longitude / latitude` **全为 0.0**，接口没给坐标。旧代码显示的 `distance`（182 / 519 / 645 / 645 / 740）是抓取时设备位置的距离，不是用户当前位置的距离。

**方案**：`STORE_GEO_FALLBACK` 人工按地址标注坐标 + `validCoord()` 判定无效后回落并标 `approx`；新增 `haversineM()`、`distText()`、`rankStores()`（返回副本不污染原数组）、`locate()`（Promise 封装，timeout 8s）。URL 参数 `store` 由「数组索引」改为 **storeCode**。UI 由 `<select>` 改为自定义 combobox（含键盘上下键 / Enter / Esc、aria 播报）。

### 2.6 用户指定 UI 视觉层级规范

四条：① 标题在组件上方、浅色、层级更高；② 下拉容器深色圆角 + 浅蓝霓虹描边；③ 主文字=门店名，次要=(营业状态)、距离·182m 降透明度；④ 最右保留向下箭头。次要信息**靠 opacity 降层级而非改颜色**，保证营业中 / 已打烊切换时色相不乱。

### 2.7 已发布上线

用户反馈「在 WorkBuddy 里点文件默认进代码编辑器，看不到网页」，遂把整个静态站点发布为在线地址。**约定**：后续改动本地文件后，必须由用户明确说「发布 / 上线 / 更新线上」才会再次部署。

## Day 3 · 2026-10-17

### 3.1 用户四条硬要求：定位弹窗改主动触发

① 初始化**禁止**自动定位、禁止自动弹失败弹窗；② 只有点击下拉框 / 「定位」按钮才请求；③ 失败才弹窗并提供【手动选择门店】【重新定位】；④ 未选门店时求解按钮置灰并提示。

**踩坑**：`moveCursor()` 里 `cur.scrollIntoView({block:"nearest"})` 在 jsdom 下抛 `is not a function`，异常会中断 `openList()`，导致写在其后的定位请求根本不执行（测试里「点击下拉框后定位次数 = 0」才暴露）。已加 `typeof === "function"` 保护，并把定位触发前移到光标处理之前。

另修：`document` 点击关闭列表的委托里补 `&& !e.target.closest("#geoModal")`，否则点弹窗里的「手动选择门店」会先打开列表、冒泡到 document 又被立刻关掉。

### 3.2 用户五条：下拉框尺寸 / 距离 / 截断 tooltip / 列表排版

- `distText()` 千米改 1 位小数；新增 `DIST_MAX_M = 200000`，> 200 km 判为坐标异常并丢弃，不再展示「几百公里」的错距离。
- 名称溢出省略，「**仅在真正被截断时**（`scrollWidth > clientWidth`）」才弹 tooltip 显示完整名称 + 地址。
- 列表行：左名称 + 地址 ｜ 中状态标签 ｜ 右距离；回显格式「门店名称 (营业中) · 109m」。
- 远距离警示条改挂在下拉面板顶部（`.sl-warn` 吸顶），按钮下方保留操作提示，页脚「数据快照来源」不动。

**验证**：南京坐标 109m / 362m / 453m / 666m / 1.1km 升序正确；北京坐标 → 距离作废并按接口参考距离排序；`distText` 边界 999m→999m、1000m→1.0km、null→"—"。

### 3.3 用户要求：热量分布图折线改散点

**理由（用户给的，很关键）**：离散单品之间不存在连续趋势，折线会误导。

实现 `scatterSVG()`：只保留渐变填充区域 path，**不再输出折线**；Y 轴上限取 `ceil(peak*1.06/50)*50`（707 → 750），刻度 0 / 200 / 400 / 600 / 700；X 轴按 `minDx = 26/sin35°` 抽稀（33 点标 12 个），`rotate(-35)` 倾斜 + 左边界 clamp；金点标记最接近目标的单品。tooltip 复用雷达那一套（命中 `.rvert, .svert`）。

> 由此沉淀为长期约定：**离散数据（单品、门店）一律用散点 / 柱状，禁止连续折线。**

### 3.4 微调

新增 `--ctl-h: 34px` 统一控件高度；`.store-row` 补 `align-items: stretch` 兜底，避免按钮写死高度后比输入框矮一截。

## Day 6 · 2026-10-24

### 6.1 用户反馈：下拉「滑不动」+ 下拉太长，压住底部数据快照

用真实 Chrome（playwright-core + `page.mouse.wheel`）逐层探查，定位到 **3 个叠加问题**：

1. **全屏遮罩遮挡**：展开下拉会自动请求定位，失败时弹出 `geoModal` 全屏遮罩盖住下拉，滚轮 / 点击全部失效 → 改为**自动定位失败只在下方留提示**，手动点「定位 / 重新定位」失败才弹窗。
2. **列表未被标记为可滚动**：面板只写 `max-height`，列表高度靠 flex 推导（非确定值），Chromium 合成器不认为它能滚，滚轮直接滚了页面 → 改为**显式 `height` + `max-height` 双写**。
3. **滚动被反复重置**：`placePanel()` 量高时先清样式再测量，页面滚动时反复抖动会把 `scrollTop` 钳回 0（「滚了又被弹回」）→ 改为直接读 `scrollHeight`（`overflow: hidden` 下仍返回内容完整高度），且值不变时不重写样式。

**顺带**：面板新增 wheel 转发（光标在搜索框 / 计数条 / 内边距时也滚动列表，滚到底交还页面）；面板高度 264 → 206（窄屏 232 → 190），**约 2 个门店条目**；下方空间同时受页脚顶约束，不压「数据快照 / 调用方法」；`.store-list` 加 `touch-action: pan-y`。

新增 `tools/browser-check.js`（真实浏览器自动化，9 项）。

> **坑备忘**：jsdom 与合成 `WheelEvent` **均无法复现**原生滚轮问题，必须用 `page.mouse.wheel` 真实输入；playwright-cli 会话在 Git Bash 下命令结束即断（Browser not open），改用 playwright-core 单进程脚本。

### 6.2 用户反馈：滚动时下拉一直缩、朝向不对，应该保持朝下

**根因**：`window` 的 scroll / resize 监听里每次都调用 `placePanel()` 重算方向 + 高度——页面一滚，按钮离视口底的距离就变，面板被反复压缩，还可能在「向下 / 向上」之间翻转。

**修复**：
1. **方向只在展开瞬间决定一次并锁定**：新增 `panelUp`，`placePanel(opts)` 仅在 `opts.reset`（`openList` 展开瞬间）决定方向；默认朝下，只有「下方连 `PANEL_MIN` 都放不下且上方更宽敞」才向上兜底；搜索 / refresh / resize 只重算高度不翻方向；scroll 监听**不再**调用 `placePanel`。
2. **高度锁定**：展开时按内容高度一次性定好，滚动页面时完全不变。
3. **顺带修掉跳页**：`openList` 里 `moveCursor` 的 `scrollIntoView({block:"nearest"})` 会把整页滚走 501px → 改为只在列表内部用 `getBoundingClientRect` 差值滚动高亮项。

**验证**（真实浏览器 12 项）：滚动 300 / 600 / 900px 时高度稳定 202px、始终朝下；展开时不跳页（`scrollY = 0`）；滚到底部仍不压页脚；矮视口 620px 兜底朝上且滚动不翻转。

## 沉淀：长期约定与踩坑清单

### 数据与算法
- 营养表只收单品，**组合词一律不做近似匹配**，否则套餐热量被严重低估。
- `DAILY`（每日推荐，雷达用）与 `REF`（单人单餐参考，环形/占比条用）**不混用**。
- 金额：菜单是**元**，`calculate-price` 返回是**分**；算价要 `productCode`（菜单叫 `code`），传错**静默返回 0**。
- `tools/call` 优先取 `result.structuredContent`；`content[0].text` 是「字段说明 + ## Original Response + JSON」包装文本，需切分。

### 图表
- 离散数据（单品、门店）**一律散点 / 柱状，禁止连续折线**。
- SVG 无 `getBBox` 时，用 `textWidth()` 估算宽度（全角 1em、半角 0.56em）来抽稀标签与防重叠。
- 倾斜标签相邻垂直净距 = `dx · sin35°` 需 ≥ 行高。

### 交互与浏览器
- 页面初始化**禁止**自动定位与自动弹失败弹窗，只在用户主动触发时请求。
- 文字溢出时**仅在真正被截断**（`scrollWidth > clientWidth`）才弹 tooltip。
- 滚动容器必须拿到**确定高度**（显式 `height`）才会被 Chromium 标记为可滚动。
- 浮层的 `position: fixed` 定位要在 `mouseover` 里立即执行一次，否则首悬浮不可见。
- `.holo` 的 `backdrop-filter` 与内部滚动容器组合时行为异常，排查时优先怀疑。
- jsdom 的 cssstyle **不解析含 `var()` 的 shorthand**，getComputedStyle 会返回 0px——是 jsdom 限制，不是代码问题。
- 本地预览：`python -m http.server 8765 --bind 127.0.0.1`（服务偶发退出，重启即可）；无头截图偶有黑帧，用 `--dump-dom` 查 DOM 状态更可靠。
